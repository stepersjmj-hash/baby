# 하이츄 — 3~6세 펜 학습놀이 앱 기획

> 대상: 만 3~6세 · 기기: 아이패드 + 애플펜슬 · 목표: 펜을 쓰는 손맛 자체가 학습이 되는 앱

---

## 1. 왜 웹(PWA)으로 시작하는가

| | 웹 PWA | Flutter | 네이티브 Swift |
|---|---|---|---|
| 윈도우에서 개발 | ✅ | ✅ (빌드는 Mac 필요) | ❌ |
| 아이패드에 올리기 | 사파리 → 홈 화면에 추가, **즉시** | Mac 빌드 + 서명 | Mac 빌드 + 서명 |
| 무료 계정 사이드로드 | 해당 없음 | **7일마다 재설치** | **7일마다 재설치** |
| 애플펜슬 필압/기울기 | ✅ Pointer Events | ✅ | ✅ (PencilKit 최상) |
| 지연시간·필기감 | 보통 | 좋음 | 최상 |
| 앱스토어 배포 | ❌ | ✅ | ✅ |

개인 사용이라면 **무료 개발자 계정의 7일 만료**가 결정타다. 네이티브로 만들면
일주일마다 Mac에 연결해서 다시 설치해야 한다. PWA는 한 번 홈 화면에 추가하면 끝이고,
오프라인으로도 돌아간다.

→ **웹으로 콘텐츠를 검증하고, 정말 배포할 만하면 그때 Flutter/Swift로 포팅한다.**
　 이 저장소의 구조(입력 정규화 / 붓 / 밑그림 / 판정을 분리)는 포팅을 염두에 둔 것이다.

## 2. 3~6세 UX 원칙 — 어른 앱과 다른 점

이 나이대는 **글을 못 읽고, 손가락이 아직 정확하지 않고, 실패에 쉽게 상처받는다.**

1. **글자 대신 그림과 소리로 안내한다.** 모든 버튼은 아이콘 + 소리 피드백.
2. **터치 타겟 64px 이상.** 지금 앱은 `--tap: 68px`.
3. **실패가 없다.** 점수·시간제한·오답 효과음 없음. 틀리면 그냥 다시 할 수 있게.
4. **파괴적 동작은 어렵게.** 전체 지우기는 **1초 길게 누르기**(진행 게이지 표시).
   설정 진입은 부모 게이트(간단한 곱셈 문제)로 막는다.
5. **되돌리기는 쉽게.** 큰 ↩️ 버튼 상시 노출.
6. **한 화면 = 한 가지 일.** 메뉴 깊이 최대 2단계.
7. **손바닥 인식(palm rejection) 필수.** 아이는 손을 화면에 얹고 그린다.
   → 펜이 닿은 뒤 1.4초간 터치 무시 + 접촉면 38px 초과 시 무시.
8. **한 활동 3~5분.** 집중 시간이 짧다. 언제 나가도 이어서 할 수 있게 자동 저장.

### B. 소근육·쓰기 준비 — **가장 중요한 축**

펜 활용도와 교육 가치가 동시에 가장 높은 영역이다. 유치원에서 하는 "쓰기 준비"가 전부 여기다.

| # | 콘텐츠 | 내용 | 교육 목표 |
|---|---|---|---|
| B1 | **선 긋기 연습** ✅ | 기본 12 + 심화 10 (별·하트·8자·꽃잎·달팽이집·큰 나선…) | 필기 기초 운동 |
| B2 | **한글 획순 쓰기** ✅ | ㄱ~ㅎ, ㅏ~ㅣ 24자 + **이름 쓰기**(가족 이름 11개, 음절 블록 조판, 칩에 **얼굴 사진**, 누르면 이름 읽기 + 글자별 읽기 + 전체 듣기) | 한글 인지, 획순 |
| B3 | 숫자 쓰기 ✅ | 1~10 + 십 단위 20~100 (낱자 획을 좁혀 조립) | 수 인지 |
| B4 | **미로 찾기** ✅ | 미로 14개 (3×2 ~ 8×5). 여정마다 주인공·목적지가 다르다 | 계획·통제력 |
| B5 | **점 잇기** ✅ | 1→2→3 순서대로 이으면 그림 완성. 집·왕관·물고기·자동차·별 | 수 순서, 소근육 |
| B6 | 알파벳 A~Z ✅ | 대문자 26자 획순 (Zaner-Bloser 계열 통용 필순) | 영문 인지 |

> **핵심 설계**: B1~B6는 전부 *"펜 궤적을 목표 경로와 비교해서 판정한다"* 라는 **하나의 엔진**이다.
> `js/core/trace.js` 를 한 번 만들면 콘텐츠 6개가 데이터(경로 정의)만 넣어 나온다.
> — 목표 경로를 점 배열로 정의 → 궤적의 각 점이 허용 반경 안에 있는지 + 진행률/방향 체크 → 통과 판정.
> **다음에 만들 것을 딱 하나만 고른다면 이것이다.**

## 6. 공통 시스템 (콘텐츠보다 먼저 설계해 둘 것)

- **진행 저장**: 활동별 완료 기록 → 스티커 지급 → 스티커북. IndexedDB.
- **부모 모드**: 진입 게이트(곱셈 문제) → 소리 on/off, 펜 전용 모드, 활동 잠금, 사용 기록.
- **손잡이**: ✅ 홈의 톱니 → 왼손/오른손. 그리는 화면에서는 버튼을 쥐는 손
  **반대쪽**에 모으고 남는 쪽을 손 쉼터로 비운다(터치 안 받음). 홈은 반대로
  쥐는 손 쪽에 둔다 — 그리지 않는 화면이라 손을 뻗게 만들 이유가 없다.
- **효과음**: ✅ 파일 없이 WebAudio 합성 (`js/core/audio.js`). 용량 0, 오프라인 안전.
  도구 10종·활동 6종이 각자 다른 소리를 낸다. 펜이 닿아 있는 동안 이어지는 소리도 있다.
  홈의 🔊 로 끌 수 있다 (부모 모드가 생기면 그쪽으로 옮긴다).
- **음성 팩**: ✅ 읽어 주는 문구 144개를 클립(m4a)으로 미리 만들어 둔다
  (`tools/make-voice.mjs`). `say()` 는 클립 우선, 없으면 기기 TTS 폴백.
  TTS 사이트에서 받은 wav 를 `assets/voice-src/` 에 넣으면 그 목소리로 교체된다.
  **144문구 전부 교체 완료** — 기계음 없이 사람 목소리에 가깝게 읽어 준다.
- **오프라인**: 서비스 워커. 차 안·비행기에서도 동작.

## 7. 기술 메모 (구현하며 확인한 것)

- `getCoalescedEvents()` 를 안 쓰면 120Hz 아이패드에서 빠른 획이 각져 보인다. **필수.**
- 애플펜슬은 접촉 순간 `pressure: 0` 을 보낼 때가 있다 → 하한값(0.4)을 둔다.
- 반투명 도구(마커)를 한 획 안에서 그대로 그리면 겹치는 곳이 진해진다
  → 별도 레이어에 그린 뒤 획이 끝날 때 한 번에 합성한다.
- 밑그림 선은 안티에일리어싱 때문에 가장자리가 반투명이라, 물감통으로 칠하면
  선과 색 사이에 흰 테두리가 남는다 → 칠한 뒤 반투명 구간으로 2px 번지게 해서 메운다.
- 밑그림은 **반드시 닫힌 영역**이어야 물감통이 샌다. 새 밑그림을 추가하면
  모서리에서 배경을 칠해 안쪽이 남는지 확인할 것 (`docs/개발.md` 의 밑그림 점검 참고).
- 예상대로 엔진 하나로 콘텐츠 다섯이 나왔다. 미로도 결국 "정해진 길 따라가기" 라서
  길을 안 그려 주고 벽만 그리면 되고, 점 잇기도 "점을 순서대로 지나는 한 획" 이다.
  화면·배선까지 공유해서 새 코스는 표에 한 줄 추가하면 끝난다.
- 다른 그림 찾기는 base/alt 파라미터를 받는 장면 함수 하나가 양쪽 그림을
  그린다 — 두 그림이 바뀐 곳 말고는 픽셀까지 같아서, 자가 점검이
  "엉뚱한 곳이 다르지 않은가" 를 픽셀 비교로 검사할 수 있다.
- 그림 자산 없이 **그림자 문제**를 만들 수 있다 — 이모지를 캔버스에 찍고
  `globalCompositeOperation='source-atop'` 으로 덮으면 실루엣이 된다.
- 잡음(noise)을 필터에 통과시키지 않으면 사각거리는 소리가 절대 안 나온다.
  사인파 합성만으로는 종·삐 소리밖에 못 만든다.
- 궤적 판정은 "진행점에서 앞쪽 구간 중 **가장 멀리 간 지점**" 을 잡아야 한다.
  가장 가까운 점을 잡으면 빠르게 그을 때 진행이 멈춘다. 앞쪽 구간(lookahead)을
  제한하는 이유는 나선처럼 경로가 자기 자신에게 가까워지는 곳에서 건너뛰지 않기 위해서다.
- 서비스 워커를 캐시 우선으로 두면 코드를 고쳐도 아이패드가 옛날 화면을 계속 보여준다
  → **네트워크 우선 + 캐시 폴백**으로 두었다. 다만 그것만으론 부족하다 —
  서비스 워커 안의 `fetch()` 도 브라우저 HTTP 캐시를 먼저 보므로
  `cache:'no-cache'` 로 항상 재검증해야 진짜 최신이 온다.
- 사파리는 **origin 단위로** 자동재생 허용·음소거·저장소를 따로 들고 있다.
  "로컬에선 나는데 배포판에선 무음" 이면 코드가 아니라 그 사이트의 데이터를 의심할 것.
