# 획순 기준 — 한글 자모 · 영어 알파벳 · 숫자

따라 그리기류(`js/trace/hangul.js` · `english.js` · `numbers.js` · `names.js`)의
**획 순서와 방향을 무엇에 맞췄는가**를 적어 둔다. 규칙 원본은
[stroke_order.json](stroke_order.json) — 글자마다 획수 · 방향 코드 · 설명이 들어 있다.

## 표준은 없다

| 대상 | 공식 표준 | 근거로 삼은 것 |
|---|---|---|
| 한글 자모 | **없음.** 한글 맞춤법 제4항은 자모의 수·순서·이름만 정한다 | 초등 국어 교과서·쓰기 교본의 통용 관행 |
| 영어 | **없음.** 교육과정마다 다르다 (Zaner-Bloser · D'Nealian · Handwriting Without Tears) | 유아용 인쇄체(ball-and-stick) 중 가장 흔한 방식 |
| 숫자 | **없음** | 필기 교본 관행 — 4·5 는 2획, 나머지 1획 |

그래서 `stroke_order.json` 의 글자에는 `variants` 필드가 붙어 있다.
**"다르게 가르치는 방식이 있다"는 표시**이지 틀렸다는 뜻이 아니다.

## 공통 원칙

1. 위에서 아래로
2. 왼쪽에서 오른쪽으로
3. 가로획 먼저, 세로획 나중 (ㄷ · ㅜ)
4. 왼쪽·위쪽 요소부터 — 쌍자음은 왼쪽 자음 먼저, 음절은 **초성 → 중성 → 종성**
5. **동그라미는 전부 상-좌-하-우(반시계)** — ㅇ · ㅎ · 숫자 0 · 영어 O 가 같다

## 우리가 고른 것 — 되짚지 않는 쪽

관행이 갈리는 글자에서는 **획을 되짚어 올라가지 않는 쪽**을 택했다.
소문자 `h` 를 한 획으로 쓰면 세로획을 내렸다가 같은 선을 타고 올라와야 하는데,
궤적 판정 엔진은 왔던 길을 되돌아가는 걸 "질러가기"와 구분하지 못한다.
아이 손으로도 어려운 동작이라 어차피 나눠 쓰는 편이 낫다.

`stroke_order.json` 의 기본값과 **코드가 다른 글자**는 다음뿐이다 (전부 `variants` 에 있는 방식).

| 글자 | JSON 기본 | 코드(`js/trace/`) | 왜 |
|---|---|---|---|
| ㅈ | 2획 (가로+왼삐침 이어서) | **3획** 가로 · 왼삐침 · 오른삐침 | 인쇄체 모양 그대로 |
| ㅊ | 3획, 꼭지는 가로 | **4획**, 꼭지는 세로 | 위와 같음 |
| ㅎ | 꼭지는 가로 | 꼭지는 **세로** | 위와 같음 |
| B | 3획 (혹 둘을 따로) | **2획** — 혹 둘을 이어서 | Zaner-Bloser 방식 |
| I | 3획 (위아래 가로 있음) | **1획** 세로만 | 산세리프 모양 |
| J | 2획 (위 가로 있음) | **1획** 갈고리만 | 위와 같음 |
| M | 4획 | **3획** — 가운데 산을 한 획으로 | 되짚기 없음 |
| R | 3획 | **2획** — 혹과 다리를 이어서 | 되짚기 없음 |
| h · n · r | 1획 (되짚어 올라와 혹) | **2획** 세로 · 혹 | 되짚기 없음 |
| m | 1획 | **3획** 세로 · 혹 · 혹 | 위와 같음 |
| Y | ① 곡선 → ② 왼아래 사선 | ① **오른아래 사선** → ② 꺾인 획 | 인쇄체 모양 그대로 |
| 1 | 세로 한 획 | **깃발 + 세로**를 한 획으로 | JSON 의 variants 그대로 |
| 4 | ㄴ꼴 + 세로 | **사선**으로 내려긋고 가로 · 세로 | 인쇄체 4 |

나머지 한글 24자, 영어 대소문자, 숫자 1~9 는 JSON 기본값과 같다.
소문자 `q`(꼬리 없는 곧은 세로) · `t`(감아올림 없는 곧은 세로)는 이 표를 보고
코드를 규칙 쪽으로 폈다 — 원래는 꼬리와 감아올림이 있었다.

## 채점은 관대하게

- 러너는 `strokes` **순서대로** 그려야 통과시킨다 — 순서가 곧 획순이다.
- 하지만 "틀렸다"는 표시는 없다. 3~6세 앱의 원칙이다(`docs/기획.md` 2절 3항).
  획을 엉뚱한 데서 시작하면 진행이 안 될 뿐, 오답 소리도 감점도 없다.
- 획순을 바꾸고 싶으면 해당 파일의 `strokes` 배열 순서만 바꾸면 된다.
  좌표는 그대로 두고 순서만 손대도 된다.

## 대조 — `node tools/check-strokeorder.mjs`

코드가 그리는 경로에서 **방향 코드를 되읽어** `stroke_order.json` 과 맞춰 본다.
좌표는 규칙에 없으니 경로 모양에서 추론한다 — 감긴 각도로 `CCW`/`CW`,
직선에서 벗어난 정도로 곧은 획, 앞뒤 진행 방향으로 `R_D`/`D_R`.

- `variants` 가 있는 글자에서 다른 건 **참고**로만 찍는다. 그 목록이 위
  "우리가 고른 것" 표와 같아야 한다 (지금 15건).
- variants 가 없는데 다르면 **FAIL**. 지금은 85자 검사에 어긋남 0.
- 글자를 추가하거나 좌표를 손보면 돌려 볼 것.

## 좌표는 여기 없다

`stroke_order.json` 은 **규칙만** 정의한다(순서·방향·획수). 실제 트레이싱 경로는
`js/trace/*.js` 의 1000×700 좌표계 `poly()`/`arc()` 가 갖고 있다.
새 글자를 넣을 때 이 JSON 으로 **획수와 순서를 확인하고**, 좌표는 코드에서 그린다.
